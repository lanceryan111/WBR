我现在建议做一个比“删掉再创建 CODEOWNERS”更安全、更有诊断价值的测试：

在 bad repo 的 master 上临时把 CODEOWNERS 简化到最小：

* @TD-Universe/wbr-dev-ops

然后 merge。

接着马上跑：

gh api \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2026-03-10" \
  repos/TD-Universe/watrp-devex-tdmoband/codeowners/errors

再开一个新的测试 PR，随便修改一个普通文件，比如 README。

这里会出现两种非常有价值的结果：

如果突然变成：

{"errors":[]}

而且新 PR 自动出现 wbr-dev-ops

→ 原来的 CODEOWNERS 内容里存在某个 GitHub backend 无法正常处理的问题。这时候我们再逐行恢复原规则，很容易定位。

如果仍然：

404 Not Found

而新 PR 依然没有 reviewer

→ 基本可以排除 pattern。问题变成 这个 repository 的 CODEOWNERS recognition/indexing 本身异常。

不过在做这个之前，我还想让你跑一个很有价值的命令。比较两个 repo 的 CODEOWNERS 原始 bytes，因为你截图里有一个细节：

tdmobios:  size 513
tdmoband:  size 514

两边不是完全一样。

把两个下载下来：

gh api \
  -H "Accept: application/vnd.github.raw+json" \
  'repos/TD-Universe/watrp-devex-tdmobios/contents/.github/CODEOWNERS?ref=master' \
  > /tmp/ios-codeowners
gh api \
  -H "Accept: application/vnd.github.raw+json" \
  'repos/TD-Universe/watrp-devex-tdmoband/contents/.github/CODEOWNERS?ref=master' \
  > /tmp/and-codeowners

先：

diff -u /tmp/ios-codeowners /tmp/and-codeowners

再跑一个特别有用的：

xxd /tmp/ios-codeowners > /tmp/ios.hex
xxd /tmp/and-codeowners > /tmp/and.hex
diff -u /tmp/ios.hex /tmp/and.hex

这个可以抓出来普通 UI 看不见的：

UTF-8 BOM
CRLF vs LF
non-breaking space
隐藏 Unicode character
行尾异常

我现在其实更推荐先做这个 byte-level diff，再改文件。

因为你两个文件 size 正好差 1 byte（513 vs 514），而 good repo /codeowners/errors 正常、bad repo 404。这个差异现在非常值得查。

如果 diff 发现只有 team/path 本身不同，那再做 * @TD-Universe/wbr-dev-ops 最小化测试。
